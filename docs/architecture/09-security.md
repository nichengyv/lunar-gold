## 1. 威胁模型

本地优先工具的信任边界与纯 Web 应用不同：

| 资产 | 风险 |
|---|---|
| 用户工作区文件 | 路径逃逸、误删、越权写入 |
| 终端命令 | 命令注入、危险子命令、孤儿进程 |
| 模型密钥 | 明文泄漏、进入日志或诊断包 |
| 会话与知识库 | 跨用户/跨项目读取 |
| 本机端口 | 其他本机进程伪造请求 |
| 外部 MCP server | 恶意工具、挂起导致长时间超时 |

设计前提：**模型输出不可信、项目内容不可信、外部 MCP 不可信**。

---

## 2. 认证

| 场景 | 机制 |
|---|---|
| 云端 | 账号密码登录，JWT 认证 |
| 桌面端 | 本机随机令牌换取，绑定回环地址 |
| 请求链路 | `JwtAuthenticationFilter` + `LocalTokenFilter` + `TraceIdFilter` |
| 会话失效 | 退出/改密后旧令牌失效，避免长期有效 |
| 启动校验 | `SecretStartupValidator` 阻止默认/空密钥启动 |

白名单仅限：`/api/auth/**`、`/api/desktop/token`、`/actuator/health` 等必要端点，其余默认认证。

---

## 3. 授权与隔离

- 所有资源查询带 `userId` 维度，避免横向越权。
- 会话、消息、Run、文档均校验归属后再操作。
- 能力门控：`CapabilityService.require` 在服务端拒绝当前部署模式不支持的能力；`@RequiresCapability` 与切面兜底。
- 管理端点（如提示词重载）限制本机调用。
- 审计：`AuditLogAspect` 记录关键操作，`RateLimitInterceptor` 限制高频请求。

原则：**前端隐藏不是安全边界，服务端校验才是。**

---

## 4. 文件安全

`WorkspaceFileService`：

1. 规范化路径，校验位于 `workspaceRoot` 内；
2. 拒绝 `..` 逃逸；
3. 已存在路径做 `realpath` 校验，拒绝符号链接越界；
4. 新建路径按父目录真实路径校验；
5. 所有读写、删除、编辑工具统一走该服务，不允许工具自行拼路径。

---

## 5. 命令安全

`CommandService` 五道限制：

| 限制 | 作用 |
|---|---|
| 程序白名单 | 只允许配置的可执行程序 |
| 工作目录校验 | 必须在工作区内 |
| 参数拦截 | 解释器 `eval`、危险 `git` 子命令、敏感绝对路径 |
| 超时终止 | 到时杀掉整棵进程树 |
| 输出截断 | 防止撑爆上下文与日志 |

OS 级回收：Windows Job Object（`KILL_ON_JOB_CLOSE`），即使命令脱离父进程也会被内核回收。macOS/Linux 对应机制未实现。

---

## 6. 审批作为安全闸门

- 写文件、删文件、执行命令等高风险操作必须审批（`READ_ONLY` 直接禁止）。
- 审批决策落库，超时即拒绝，重启不恢复为可批准。
- 拒绝原因回灌模型，避免模型反复尝试被拒操作。
- 会话级“总是允许”只在当前会话生效，不扩大到全局。

---

## 7. MCP 安全

- 全局开关默认关闭，关闭后调用直接拒绝。
- 只连接 `allowed-servers` 白名单中的 server。
- 健康监控熔断，避免外部 server 挂起拖死主流程。
- 工具注册去重，失败返回可读原因，不暴露内部堆栈。
- 外部 server 自身行为不在本项目控制范围内，需用户自行评估来源。

---

## 8. 密钥与隐私

- BYOK 密钥按用户存储，接口不回显明文。
- 日志与诊断包按白名单脱敏：路径替换为 `<PATH>`，不含对话、知识库、数据库内容、模型 Key、本机令牌。
- 诊断默认只存本地，无远程上传。
- `.env`、`application-dev.yml`、`uploads/`、`data/` 等已加入忽略规则。

---

## 9. 现状边界

- 仅 Windows 具备 OS 级进程沙箱。
- 安装包未签名，SmartScreen 会提示未知发布者。
- 双实例下审批互斥未实现。
- 没有第三方渗透测试与依赖漏洞持续扫描。
- MCP server 的供应链安全依赖用户选择。

---

## 10. 面试要点

1. **本地应用为什么还要认证？** 本机端口可被其他进程访问，必须有令牌与回环绑定。
2. **如何防路径逃逸？** 规范化 + 前缀校验 + `realpath` 三重检查。
3. **如何防命令注入？** 白名单 + 参数拦截 + 目录约束 + 进程树回收，多层防御。
4. **为什么审批要落库？** 安全决策必须可恢复、可审计，不能只存在内存里。
