## 7. 关键注意事项 / 踩坑记录

### 7.1 PS1 脚本 BOM 问题（反复踩坑）

- Windows PowerShell 5 解析 UTF-8 脚本**必须有 BOM**，否则中文乱码
- 但编辑器（VS Code / 某些 IDE）反复保存会**叠加 BOM 层**（单→双→三→四），导致 PowerShell 报 `Unexpected attribute` / `TerminatorExpectedAtEndOfString`
- **修复方式**：用 PowerShell 读取首字节，去掉多余的 `EF BB BF` 层，只保留一层
- **预防**：编辑 PS1 脚本后检查首 3 字节是否为 `EF BB BF`（单 BOM）

### 7.2 CI 上的编码陷阱

- `.github/workflows/release.yml` 里 `run: |` 块的 PowerShell 脚本，**中文字符串会被当 GBK 解析**（因为 YAML 是 UTF-8，但 CI runner 的 PowerShell 编码页是 GBK）
- 表现：`throw "中文消息"` → ParserError 引号未闭合
- **修复**：所有 `throw` / `Write-Host` / 非注释中文字符串改为英文；注释可以保留中文（不被解析）

### 7.3 Electron 下载

- Electron npm 包只装 JS wrapper，`dist/` 二进制靠 postinstall 从 GitHub releases 下载
- CI runner 上 `install.js` 经常卡死（37min+ 无输出），不是慢，是连接没建立
- **修复**：用 `curl.exe` 直接下载 zip + `Expand-Archive` 解压，有 `--connect-timeout 30` + 进度输出
- 缓存路径 `~/.cache/electron`，用 `actions/cache@v4` 持久化

### 7.4 GitHub Actions 缓存机制

- runner 是临时 VM，每次 run 结束销毁
- 没有 `actions/cache@v4` 显式保存，`~/.cache/electron` 会随 VM 销毁
- 缓存有"鸡生蛋"问题：第一次 run 必须先下载成功并存缓存，后续 run 才能命中
- key 用 `hashFiles('desktop/package-lock.json')`，lock 文件变了缓存失效重新下载

### 7.5 Re-run tag-triggered run 的陷阱

- `git tag v0.1.3` 触发的 run，checkout ref = `refs/tags/v0.1.3`，指向 tag 对应的 commit
- **Re-run 同一个 run 不会更新到 master 最新**，还是用 tag 指向的旧代码
- 修复推到 master 后，要重新打 tag 或用 `workflow_dispatch` 手动触发（选 master 分支）
